======================================================================
一、总体结论
======================================================================
Minimum 语义主链已基本成形：manifest/typed runtime 是唯一生产入口，envelope/
route/ingress、生命周期协调、成员控制、block 收发链、内核 per-VM context 都有
真实实现与针对性测试。

但 Minimum 仍未闭合，关键缺口：
  1) 存储放置未实现：admission planner 明确把 storage_assignments 置 0，
     因此真实 manifest 里没有设备归属，block 链只能在测试自造投影下运行。
  2) R06 仍未证明“指令执行依赖远端页内容”；现有证据只是一次远端读。
  3) R08 canonical 双实现为 49/52，仍有 3 个复合记录没有独立双实现夹具。
另有若干规范 §8 已列出的内存一致性迁移项仍未关闭。

2026-10-21 Codex agent 重点复核结论（已并入本报告）：
  R02 链路部件已接；planner 已支持 storage template 固定，但正常
      CREATE_VM 仍不提交设备模板 -> PARTIAL；
  R03 保留期/ACK 已修，vCPU 在途引用已接并带 in-flight deadline -> PARTIAL；
  R04 pre-image 不丢是进步但失败无用户态消费者/pause -> PARTIAL；
  R05 master 别名方向正确、slave 单写者假设未验证 -> PARTIAL；
  R08 仍为 49/52 -> PARTIAL。
  另纠正：guest 登录/SSH + 远端 CPU/内存证据属于 Minimum（goal §7），
  只是最后执行，不是 Extended。本报告已按此修正，未用 DONE 标签收口。
  该复核是重点核对，不是对全部改动的完整重审。

二、Baseline 逐条
======================================================================
§1 项目目标
  分布式 QEMU 定位、Minimum/Extended 两档、多节点 CPU/内存池化：DONE（架构与
  主链）。证据：node_runtime/main.c（统一节点运行时）、gateway_service/
  aggregator.c、common_include/wavevm_envelope.c、wavevm_route_runtime.c。
  Minimum 本身：PARTIAL（见上文三缺口）。

§2 非目标
  未发现按测试硬编码 node/port/vm 的生产开关；但旧 NODE/ROUTE 引导输入仍被
  gateway 解析（gateway_service/aggregator.c），属于纲领允许的 bootstrap
  兼容；Phase 0 要求“从生产输入移除”，当前仍保留，记 PARTIAL。
  未发现 KVM/TCG 双产品化、Mode A/B 双控制面：DONE（统一 envelope/服务层）。

§3 规范架构
  控制面 / QEMU 前端 / 节点运行时 / executor / gateway / 可选内核加速器分层
  存在。证据：ctl_tool/main.c、wavevm-qemu/accel/wavevm/、node_runtime/main.c、
  node_runtime/executor_bridge.c、gateway_service/aggregator.c、
  master_core/kernel_backend.c。DONE。

§4 组件边界
  4.1 用户态控制面：admission orchestrator/recovery/controller 已实现
      （common_include/wavevm_admission_orchestrator.c、
       wavevm_admission_recovery.c:272,382、wavevm_membership_controller.c）。
      PARTIAL：单活协调器，无 HA（V1 允许）。
  4.2 QEMU 前端：加速器 glue + 远程切换 + block hook
      （wavevm-qemu/accel/wavevm/wavevm-all.c、
       hw/wavevm/wavevm-block-hook.c、hw/block/virtio-blk.c）。DONE。
  4.3 节点运行时：node_runtime/main.c、ingress.c、memory_service.c、
      vcpu_service.c、block_service.c；manifest/dispatch/route 校验在
      main.c:517-540,637,1249。DONE。
  4.4 executor：node_runtime/executor_bridge.c、executor_session.c、
      wavevm_executor_abi.c、slave_daemon/slave_hybrid.c。DONE（typed ABI），
      但 slave_hybrid 仍是独立执行文件，属兼容实现。
  4.5 节点运行时/executor 边界：typed ABI 已存在；旧 master→slave UDP 头仍在
      master_core/user_backend.c、main_wrapper.c 的兼容路径中使用（非 typed
      路径）。PARTIAL。
  4.6 gateway：envelope 解码 + 路由快照查找
      （gateway_service/aggregator.c:614-625）。DONE。
  4.7 内核加速器：per-VM context（kernel_backend.c:132-166），模块级 socket/TX
      ring 带 context 标签（kernel-accelerator.md §1.2）。PARTIAL：仍有
      context-tagged 模块级 plumbing。

§5 Mode 模型
  Mode B 为语义基线、Mode A 为加速器：DONE（docs/specs/kernel-accelerator.md；
  统一 envelope/服务层）。
  Mode A 多 VM：门仍然关闭。证据：common_include/wavevm_admission.c:1052-1075
  以固定 "kernel-context" 独占租约拒绝第二个 Mode A；common_include/
  wavevm_ioctl.h:59 说明 QUERY_CAPS 仍报 SINGLE_CONTEXT/max=1。符合纲领当前
  状态（A01–A04 未闭合前必须拒绝）。

§6 执行后端
  KVM/TCG 共享 handoff/内存契约：DONE（docs/specs/vcpu-handoff.md、
  node_runtime/vcpu_coordinator.c、vcpu_service.c）。
  同 VM 后端同构、跨后端 handoff 拒绝：DONE（vcpu-handoff §4/§6）。
  AUTO 优先 KVM、REQUIRE_KVM 不降级：DONE（capability/placement 选择；
  common_include/wavevm_host_probe.c、wavevm_admission.c 能力选择）。
  KVM dirty/resync：PARTIAL（最低真实探测已实现，见 R07；完整 dirty 合流仍属
  Minimum 的 KVM 路径验证项）。

§7 多 VM 模型
  7.1 复合身份/vm_incarnation：DONE。envelope 固定头携带 u32 vm_id + u64
      incarnation（common_include/wavevm_envelope.h、wire-ipc-abi.md §1.3）。
  7.2 per-VM 隔离：DONE（manifest 派生名字：wavevm_runtime_names.c；测试：
      tests/control-plane/test_same_host_dual_agent_live.sh）。
  7.3 host placement 显式：DONE（placement plan 的 host_node；
      common_include/wavevm_admission.c 生成；request origin 不再隐含）。
  7.4 原子准入：DONE（生命周期 ACTIVATION_DECIDED 栅栏 + recovery；
      wavevm_admission_orchestrator.c:666-679、admission_recovery.c:272）。
      PARTIAL：存储预留未纳入（见 §8）。

§8 资源模型
  8.1 节点注册/能力：DONE（wavevm_membership_controller.c、admission
      snapshot）。
  8.2 VM 请求：DONE（wvm_vm_request，ctl_tool）。
  8.3 compact/spread 确定性：DONE（admission.c placement 逻辑，测试
      test_placement_plan）。
  8.4 guest NUMA：PARTIAL（flat 默认；placement-aware/synthetic 为显式选项，
      未见完整实现；纲领允许）。
  8.5 成员/拓扑生命周期：PARTIAL。NodeRecord/GatewayRecord、状态机、
      prepare/ack/commit/retire 已实现（wavevm_membership_controller.c、
      wavevm_route_control.c、wavevm_control_transport.c）；V1 仅单 scope
      gateway drain，聚合多 scope/host 事务为 Extended。
  **storage placement：ABSENT**。common_include/wavevm_admission.c:1400 明确
  placement_plan->storage_assignments.count = 0；请求也只带 device config
  digest，没有设备数/容量需求。这是 block 链无法在真实集群上跑通的根因。

§9 一致性模型
  directory/version/subscriber 语义与操作：DONE（node_runtime/
  directory_store.c、memory_service.c、wavevm_memory.c）。
  spec §8 列出的迁移项仍未全部关闭：PARTIAL。
  已知未闭合项（与 memory-consistency.md §8 对应）：
    - 部分 commit ACK 仍不带结果版本；
    - 版本追赶异常缺少显式 writer lease/resync 证明；
    - MSG_MEM_WRITE 仍有 versionless 路径；
    - SYNC_MAGIC 未按 VM incarnation 作用域；
    - 内核 logic_core 仍保留目录/路由语义副本（Mode A 路径）；
    - page lock 内推送/通知；
    - subscriber 过期/移除策略未完全实现。
  这些在代码中仍可定位到 master_core/logic_core.c、slave_daemon/
  slave_hybrid.c、kernel_backend.c 的对应路径。

§10 网络与路由
  严格复合键、非零 vm_id 不回退 raw ID：DONE（identity-routing.md；
  wavevm_route_runtime.c:554-601；gateway aggregator envelope 路径）。
  路由快照按 generation 原子发布、prepare/ack/commit/retire：DONE
  （wavevm_route_control.c、wavevm_route_runtime.c、control_transport）。
  健康心跳不改变生产路由：DONE（控制面注册/快照路径；gateway 静态 ROUTE
  仅 bootstrap）。
  多 Pod/fractal：DONE（route runtime FRACTAL 查找 + gateway prefix 规则；
  测试 test_route_runtime/test_block_topology）。

§11 存储与设备
  QEMU 宿主为设备权威、远端 block 经节点运行时：DONE（block hook →
  main_wrapper → block_client → envelope → 目标 ingress → block_service →
  chunk store → ACK）。证据：wavevm-qemu/hw/wavevm/wavevm-block-hook.c:124-127,163-166、
  master_core/main_wrapper.c:1338-1460、node_runtime/block_client.c、
  node_runtime/block_service.c、common_include/wavevm_block_wire.c。
  设备身份：DONE（请求头 device_index；QEMU 侧按设备注册表分配，
  virtio-blk.c:687,732）。
  FUA/FLUSH：DONE（block_service 执行 FUA；测试覆盖）。
  缺口：QEMU block hook 仅在 WVM_BLOCK_IO=1 时启用
  （wavevm-block-hook.c:80），默认路径仍是本地磁盘；存储放置缺失使真实
  manifest 无法声明远端设备；flat/fractal 只做了路由层合同测试，未过网关进程。

§12 环境能力
  capability probe（KVM/TCG/UFFD/kernel accel）：DONE（wavevm_host_probe.c）。
  选择规则（缺席快路径→慢路径，无正确路径早失败）：DONE（capability 选择 +
  REQUIRE_KVM 拒绝降级；test_host_probe）。
  UFFD：ABSENT/EXT（规范列为可选引擎）。

§13 Mode A 重定位
  用户态语义权威、内核仅加速：PARTIAL。per-VM context 与 BIND 已实现
  （kernel_backend.c:2738；ioctl.h:110），但内核仍保留部分目录/路由副本
  （kernel_backend.c 中 kernel-linked logic_core），需继续迁移。

§14 多 VM 与内核加速器
  显式 per-VM context、BIND/ATTACH、引用计数、销毁：DONE
  （kernel_backend.c:132-166,631-700；tests/mode-a/）。
  A01–A04 隔离正确性未闭合前门保持关闭：符合纲领。

§15 不变量
  Mode B 基线、KVM/TCG 同语义、flat/fractal 同命名空间、多 VM 默认隔离：
  DONE（见 §5/§6/§7/§10）。
  “成员移除先 drain、running VM 不静默重绑”：DONE（V1 拒绝 busy compute
  移除；gateway 需确认替代路径；wavevm_membership_controller.c、
  route_control.c）。
  “不得用全局串行/同步转发替代正常并发路径”：PARTIAL。block service 的
  执行按队列锁序列化（block_service.c，queue_locks），master/slave 兼容路径
  仍有串行点；未发现新的全局大锁，但需要后续评审。
  “测试脚本不得成为运行时真相”：PARTIAL。NODE/ROUTE 仍存在于 bootstrap，
  测试仍大量手工配置；纲领允许作为过渡但 Phase 0 要求移除。

§16 V1 决策
  版本化 request/manifest、显式 host_node、host overhead、all-or-nothing 启动、
  durable activation、单活协调器与重启恢复：DONE/PARTIAL 混合。
  证据：wavevm_manifest.c、wavevm_lifecycle.c、admission_orchestrator.c、
  admission_recovery.c。host overhead 为显式预留字段（manifest reservation）。
  单活协调器重启恢复：DONE（ACTIVATION_DECIDED 重放/补偿，recovery.c）。
  u32 vm_id / incarnation 隔离、路由严格键：DONE。
  跨后端 handoff、live migration、HA、自动 rebalance：未实现，纲领列为
  Extended/未来工作，符合预期。

§17 GiantVM
  仅参考，无实现义务。DONE（未引入其硬依赖）。

§18 立即决策
  规范先行、Mode B 权威、KVM/TCG 同契约、内核只加速、节点运行时/执行器边界、
  成员/路由快照控制面化：整体遵循，DONE（除 §4.5/§13 的残留兼容路径）。

   in-flight deadline 到期时 put；超时降级为 ETIMEDOUT。剩余：真实 retire
   ACK 竞争下的 E2E。
