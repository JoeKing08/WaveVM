一、最终结论

MINIMUM_COMPLETE=NO。
不是只差 TCG login，也不是整个重构只剩骨架。生产 CREATE authority、participant
事务、typed 数据面、资源放置、同机多实例、Mode A per-VM context 都已有实质实现。
但并发分布式 TCG 尚有 guest panic；补跑还发现 KVM 启动验收顺序、双 VM STOP、
Mode A 生产执行探针的失败。源码另有若干内存和故障收口缺口，必须一起收住。

下面 F01-F10 是去重后的必收口项，包含生产缺陷和测试入口问题，并非十个已确定
根因彼此独立的生产 bug。Q01-Q03 是条件性/补证事项；矩阵失败不再另算一批 bug。
每项写明证据、修复方向、完成判据。按“生产路径 -> 编译/少量定向验证 -> 下一条”
推进，最终再做 guest 矩阵；不需要每修一个函数都跑整套测试或新造一层框架。

纲领权威：docs/wavevm-architecture-baseline.md、docs/wavevm-refactor-roadmap.md
及其引用的 docs/specs；goal.txt 和持久化plan.txt 是实施安排，不覆盖纲领。
本次没有修改纲领、生产源码或执行修复，也没有提交/推送。

三、必收口项

F01 [P1，实测失败] 并发分布式 TCG 的 guest 正确性和主路径仍未成立。
依据：baseline §16；vcpu-handoff.md §8.1。
证据：audit-evidence/fix-blockers-20261103/
  s55-apic-vector-diagnostic/vm-serial.log:132、185：scheduling while atomic、NULL fault。
  s56-shared-backing-trace/vm-serial.log:260、322：NX instruction-fetch fault、init panic。
  s56-shared-backing-trace/result.txt：guest_login=MISSING。
  s32-all-local-2vcpu-183313/result.txt：全本地 login/SSH/CPU PASS，远端内存增量为零。
旧对照：audit-evidence/fix-blockers-20261030/s23-tcg-contract/flat_tcg-s23g17h/
  result.txt 虽 OVERALL=PASS，但 remote_done_delta=12、force_local_used_delta=7971，
  B6_STATUS=PARTIAL、fl_dominates=yes，不能满足“远端并发为主、非涓流”的合同。
方向：从最后可复现的坏状态定位 CPU/中断/原子操作交接和内存可见性；保留原生
QEMU、全本地 WaveVM 对照。已有 EXCP_ATOMIC bounce，不要重报成完全没有该实现。
同源 full-page push 覆盖活动 RAM 的旧缺陷已有修复，但 s56 仍 panic，尚非唯一根因。
完成：至少双 vCPU 的本地 BSP + 远端 AP 并发配置通过 login/SSH、CPU/内存负载、
远端有效进展和 STOP；force_local 只在可解释的有界例外窗口内使用。不得靠永远
全本地、STW 默认、延长 sticky fallback、伪造 HLT/ACK 或镜像特判过关。
注意：BSP 按计划留本地是合法的；CPU0 remote_done=0 本身不是 bug。

F02 [P1，确定有失败；已发现夹具顺序问题] KVM CREATE/readiness 验收无法完成。
证据：E/S6/SUMMARY.txt 的两个 KVM 格；E/guest-kvm/flat_kvm.create.log。
反复 status=14/recorded_state=9，runtime 等待 manifest-bound QEMU frontend 注册。
定位：tests/e2e/test_guest_smoke.sh:113 起先同步调用 CREATE 脚本；
test_create_vm_single_node.sh:317 起等 SUCCESS/RUNNING 后才返回；guest 脚本约 :238
才启动 frontend。这与 runtime 必须先看到 frontend 才 ready 的要求形成顺序循环。
方向：明确 frontend 的启动/所有权责任，在合法 activation/manifest 已具备后、
等待 RUNNING 之前启动并注册 frontend，禁止未准入 guest 流量。若生产入口本应
启动它，同样补真实 child 启动/失败上报。不能把 RUNNING 改为跳过真实 readiness。
完成：flat/fractal KVM CREATE -> frontend 注册 -> RUNNING -> typed 执行通过，
再补 guest；超时有界收尾。S6 的 class=memory/route 是启发式分类，不是已证实根因；
现有日志也不足以断言 KVM 指令执行或内存一致性本身已经回归。

F03 [P1，实测失败] 双 VM 的 STOP/资源清理在当前路径失败。
依据：runtime-manifest-lifecycle.md STOP/退役；roadmap Minimum 多 VM、清理要求。
证据：E/S6/mode_b_dual.stop_summary.txt、mode_b_dual.ctl.log。
两个 VM 曾 CREATE/RUNNING，VM1 child 被有意杀掉后，VM2 仍能执行 typed 探针；
但 STOP 两 VM 都 status=6，错误为 control target does not match the membership
snapshot，随后残留 VM2 的 SHM/socket/ready 文件。Mode A 双 VM 也有收尾失败。
定位：common_include/wavevm_admission_transport.c:200 的 resolve_member_target；
wavevm_admission_orchestrator.c STOP participant_abort；ctl_tool/admission_recovery.c。
方向：核对持久化 candidate/runtime/activation、当前 membership 的 role/node
instance/endpoint，以及 STOP 的 participant target 投影。保留身份校验；不能删校验、
使用任意新实例顶替旧实例，或把旧 incarnation 的资源当成当前实例资源清掉。
完成：健康 VM 和已 FAILED/DEGRADED VM 都能按确切身份 STOP/退役；停止 A 时 B
继续执行，之后 B 也可正常 STOP，无属于本 run 的名字/lease/路由/进程残留。
测试子进程被杀后的清理不等于透明恢复，不要求实现 RECOVERY_REBIND。

F04 [P1，实测失败，根因待定位] Mode A 生产 typed short-exec 未完成 guest store。
证据：E/S6/mode_a_one.dataplane_detail.txt；S6 mode_a_dual。
CREATE 已 SUCCESS/RUNNING，真实 QEMU，VM ID=256；探针经 typed WVM1 ingress，
期望 marker=0x5266，SHM 读到 0x90909090 而超时。该单格 via_gateway=0，不能
只凭探针标题中的 ingress/gateway 就断言 gateway 本身坏了。
方向：逐段核对 ingress -> vCPU service -> executor -> QEMU -> memory commit
和完成结果；检查 Mode A 新的 kernel/user memory bridge 与 backing 身份。
完成：这条真实生产路径能完成 guest store，再验证双 Mode A 执行及 STOP 隔离。
现有四个真模块隔离测试通过，不能把本项重述为“per-VM context 完全没做”。
也不能把探针改成绕过 ingress 的直发 UDP、stub 或只查进程存活。

F05 [P1，源码缺口] 本机 SHM 共享证明不足以关闭跨主机 TCG 的缺页路径。
依据：memory-consistency.md；vcpu-handoff.md §8.1 same-host 前提。
位置：wavevm-qemu/accel/wavevm/wavevm-all.c:2170、2424、2443；
wavevm-user-mem.c:65、81、3679；wavevm-cpu.c:239；slave_hybrid.c:2315。
JOIN/attach 成功只证明本机 helper/runtime 共享；同一 coherent 布尔量却关闭 slave
fault hook，并用于选择 concurrent 调度。未核对 frontend 与执行参与者的物理
主机/backing 关系。可选首地址预取不能代替任意地址的真实远端缺页/同步。
方向：区分本机 backing 共享与本次 CPU 交接双方 RAM 共享，由 admitted placement
选择正确路径；跨主机保持真实缺页/版本/同步。未证明共享则不可静默走共享快路径。
完成：同机快路径保持，跨机 CPU-only executor + memory-only 节点也能读写、提交；
不支持的组合先明确拒绝，但拒绝不能冒充分布式资源池化完成。
本项是源码适用范围问题，不指认为当前同机 s56 panic 的已证实根因。

F06 [P1，源码缺陷] 非 coherent TCG 写页池会覆盖仍在队列中的节点/快照。
位置：wavevm-user-mem.c:156、1852、1872、3754。
PAGE_POOL_SIZE=4096，fetch_add %4096 直接复用 WritablePage/pre-image，无占用保护；
TCG 到 handoff 才排空。超过 4096 个未消费写缺页会覆盖快照并破坏链表，可能环链。
方向：明确槽位占用/归还，提交或撤销后再复用；耗尽时有界背压或执行失败，不能
覆盖未处理项。保留 MPSC/批处理，不以全局锁串行所有页解决。
完成：超过池容量的脏页负载得到正确提交或可解释的有界失败，链表不坏、无错误 diff。
这是受限 fallback 的独立问题，不把它当作 coherent guest panic 的确定根因。

F07 [P2，规范接线缺口] subscriber 主动失效/过期生命周期不完整。
依据：memory-consistency.md §4.5，ACTIVE->STALE 与成员失败/scope 退役规则。
位置：node_runtime/memory_service.c:993、1016、1063、1107、1144；.h:127。
已有新实例同 GPA 读取时废弃旧订阅、发送失败标 STALE、STOP 销毁；但 epoch/lease
只赋值未用于过期判断，reap 不使 ACTIVE 过期，也没有成员/scope 控制器主动失效接线。
方向：成员实例失败/替换、scope 退役回调及实际 lease/epoch 校验；失效后重新取得
读资格。正常 G->G+1 路由提交不应无差别使健康订阅失效。
完成：旧实例不能留下有效订阅资格或无限占用表，重新读后才重新合格。
HINT 是 best effort，不要求每个订阅都 FENCE_REQUIRED；本地发送成功不再推进
observed_version 的修复已经存在，不重复要求修它。

F08 [P1，生产接线缺口] 控制面记为 FAILED 不等于真实 runtime 已 fail-closed。
依据：roadmap §1.1:106-110、Phase 7 node-loss；baseline §16。
位置：wavevm_control_plane.c:3844-3940、2588；wavevm_runtime_gate.c:814；
ctl_tool/admission_recovery.c:1397；node_runtime/admission_main.c 的主循环。
健康 reconcile 推 journal 的 RUNNING->DEGRADED->FAILED，但没有闭合存活 runtime
的 quiesce/gate revoke。authorize 仍看本地 ACTIVE manifest；也未见 coordinator
消失后执行资格的有界失效机制。暂不访问丢失节点的本地 CPU 不能靠下一次 RPC 失败
保证及时停止。因此不能以 LIST_VM 状态变化代替实际执行边界。
方向：明确基本故障政策，接入 per-VM 真实执行暂停/拒绝门；coordinator 消失要有
有界处理，激活资源保持到安全清理。不是要求 HA、迁移、rebind 或透明恢复。
完成：少量定向用例证明必需成员/协调者消失后，相关 VM 不再继续被授权执行，
不误伤另一 VM，后续 STOP 能按身份清理。完整故障矩阵仍属 Extended。

F09 [P2，明确违约] 生产 CREATE/STOP 持全局 owner 锁等网络，阻塞无关 VM/健康处理。
依据：runtime-manifest-lifecycle.md §7；resource-placement-admission.md §6.3。
位置：ctl_tool/main.c:379-394、STOP 分支、健康循环约 :2024。
context->lock 覆盖整个 orchestrator 的远端 prepare/activate/commit/readiness；
STOP、健康 reconcile 用同一把锁。预约库的四并发 PASS 不等于生产 ctl 并发成立。
方向：journal/plane/预约短临界区，事务按 VM/冲突节点 fencing，网络等待移出全局锁，
返回后重验；不能直接删锁造成双分配。完成：一个延迟 participant 不阻塞无冲突
VM 生命周期和健康检查，同时冲突预约仍原子，四并发不会双分配。

F10 [P2，测试入口确定损坏] 修好测试构建，并使最终成功判据符合合同。
证据：E/tests/test_goal4.out、test_coordinator.out；原始源码可直接确认。
  test_goal4_executor_remote_memory.c:441 的 source_shared_backing 参数未使用，
  :493 又在无此参数的 complete_remote_fault 中使用，-Werror 编译失败。
  test_coordinator.sh 少链接 readiness 新依赖，undefined reference to
  wvm_admission_transport_query_runtime_ready。
方向：正确迁移 callback 语义和链接依赖，不能删断言或加空 stub。先恢复这两个
低成本入口，再取得真实 TCG/KVM executor + remote-memory 成功完成证据。

成功判据也需同时收口：
  test_guest_smoke.sh 约 :483 只查 remote_delta>0，会放过旧版 fl>>remote PASS；
  bounded fallback 检查可选且缺失只 WARN。按每个被远端分配的 vCPU/明确负载窗口
  记录进展、fallback 原因与持续时间，能拒绝 token trickle 和违反 30s/90s/25s 的结果。
  不要把本来本地执行的 BSP 混进比例，不凭不同长度 slice 的裸计数捏造性能阈值；
  固定可解释的判定方法，不能看完结果再调阈值让它过。
  同脚本约 :553 先 kill frontend 再 STOP，只证明死 frontend 后的清理；必须补
  对仍健康运行 guest 发起 STOP 的证据，必要的内部停机由生命周期 owner 负责。
  test_guest_minimum_matrix.sh 的 fail=0 可能仍包含 SKIP/选子集。保留局部运行功能，
  但完整验收必须区分全四格通过、部分通过、缺能力未验，不能用缺格 PASS 收尾。
完成：这些判定器的小测试通过；它们只证明判定器，不等于真实 guest 也已通过。

四、条件性问题与补证，不能直接放大成确定根因

Q01 块服务的多设备地址空间 [条件性 P1]。
node_runtime/main.c:408-447 检查 device_index 已准入，却不把该 index 传给 chunk
后端；wavevm_block_chunk_store.c 的路径只有进程级 identity 和 LBA chunk。
placement storage_templates 允许不同 device_index，可能同 LBA 落同文件。
若这条服务开放多盘，必须实现 device->backend 映射和双盘隔离；若只支持一盘，
准入明确拒绝第二盘并确保所有入口一致。普通 QEMU 本地盘是合法 Minimum 方案，
本报告不要求为了收 Minimum 新增远程磁盘。

Q02 gateway drain prepare/commit 有新失败，先复现分层，不直接宣判 gateway 算法坏。
E/tests/test_gateway_drain_prepare_commit.out：前置 CREATE 先 status=14 后 status=6，
日志出现 cannot construct route snapshot，后续 prepare 被拒绝。先区分真实错误
与沿用未清空的 error 字符串，保留当次 route/candidate/participant 状态定位。
测试没跑到目标操作不等于 drain 一定坏了，但也不能算本次成功验收。修 F02/F03 后
补跑这条链；若仍失败再作为成员/路由生产缺陷处理，勿另起一套旁路。

Q03 补齐声明能力的有限验收。
  - Mode A：四个真模块隔离测试本轮 PASS（含 2101/2102），补 F04 的非本地
    typed/内存路径与双 VM 收尾，确认 u32 身份经过真实用户态 bridge 不串 VM。
  - KVM dirty/resync：page-cache 单测 PASS，继续补真实 memslot 写脏、提交、
    版本落后/失效后重拉的定向证据；能力位存在不等于该路径已验收。
  - >4096 vnode：Codex 新夹具两条 NodeRecord 各 2050 vnode，flat 4100 route、
    fractal 4100 vnode+2 PREFIX，capture->snapshot->admission->route lookup PASS；
    单独 4096 预算溢出夹具也 PASS。它不是 4100 个物理成员 TLS 入群；按宣称容量
    补独立域预算、记录/prepare/ACK 存储边界即可，不要求 4100 台机器实测。
  - 异构 KVM CPU profile：已有上下文/CPUID/MSR 验证，不重造完整 CPU 模型框架；
    用定向反例确认不支持的目标在执行前被拒绝，不能用同构小指令外推任意异构兼容。

五、汇总时更正或收紧的独立报告说法

1. 不采纳“Mode A 没有 U32 准入检查”的确定缺陷结论：
   wavevm_coordinator.c:1153 对 selected_members 检查 WVM_CAPABILITY_ID_VM_ID_U32，
   :1195 设置 namespace_abi=U32；host_probe.c:449 发布此能力。
   内核已无独立网络目录语义，经 node_runtime/kernel_memory.c 走用户态 typed
   服务，不能要求恢复另一套内核 FULL_VMID 网络栈。Q03 的真实跨节点补证仍要做。
2. 不采纳“plan 最后只更新到 10-30”：当前顶部有 11-01/02 计划和 11-03 复盘、
   证据与后续方向。后续更新当前状态即可，勿因快速审计误读而重新造 plan。
3. Codex 原报告只采用自己跑过的测试；现在补入 DSH 的真模块隔离 PASS，以及
   S6/guest 新失败。未在本轮重跑不能一律当功能缺失；旧 PASS 也不能覆盖改过的路径。
4. KVM readiness 失败不能直接算 KVM guest panic；Mode A 探针失败不能直接算
   gateway 故障；启发式 class、错误字符串或“没到 login”不能单独证明根因。
5. 工作区 dirty 本身不是产品 bug，也不强制先 commit 才允许验收。验收要能准确
   还原源码/二进制：记录 HEAD、tracked patch、相关 untracked 新源码和构建参数/
   hash。已有 SOURCE_IDENTITY.patch 不自动包含所有未跟踪源码。最终提交有助于
   复现，但不能只写 HEAD 哈希让 dirty 结果看似来自旧提交。
6. 纲领本轮未发现新的大段进度日记污染；修复进展/审计编号写 plan/证据，不把
   此报告改写进 normative docs。没有依据把未完成 Minimum 移到 Extended。
