四、确认需要修的事项

以下 G 编号是本次统一编号，括号里保留原报告映射，方便逐项回应。
G1–G9 是 Minimum 正确性/验收阻断，按 P1 处理；G10 是 P2 构建缺陷，
应先顺手修掉以恢复验证入口。不沿用 DSH 把编译失败也标成 P0 的分级。

G1. 生产 Mode A 使用 U32 VM ID，内核 fault/dirty/RX 却仍是 8-bit
    [Codex R6-2；CC N1；DSH D1]

确认：wavevm_identity.c:122 让 U32 分配器从 256 起；:183 跳过 <256；
wavevm_coordinator.c:793–795 的正常 CREATE 固定申请 U32 namespace。
kernel_backend.c:844–852 却拒绝 vm_id>255；fault 有置 slave_id=0 后继续
发送的分支，dirty 有释放任务后退出的分支，RX 仍有 8-bit 身份解码。
所以这不是“也许将来建到第 256 台 VM 才发生”，正常生产分配已落在此范围。

要求：把 accelerator 操作接进保留完整身份的 canonical node-runtime 数据
路径，覆盖 fault/read、dirty commit 和回包关联；不能只改 BIND 结构的位宽。
worker_failure 从 2101/2102 改成 91/92 只绕过了问题，需恢复生产 ID 范围的
真实 fault/write 验证。可以暂时拒绝不支持的 Mode A 准入来防止假 RUNNING，
但这种拒绝只是安全门，不算完成纲领要求的 Mode A。

G2. SHM 本地 alias 被当作整个分布式内存合同的豁免，失败还可置 coherent
    [Codex R1；DSH D5，以及其 guest handoff 观察]

wavevm-all.c:1982/2141 默认因接上本实例 SHM 就启用 g_tcg_shm_coherent；
wavevm-user-mem.c:1730/2296 随后跳过 dirty flush/commit；handoff 也跳 fence。
不同 compute instance 的文件并非自动共享，同一物理机也不例外。
此外 wavevm_join_shared_ram_ptr 返回 void，dup/mmap 失败只退出；调用者
仍可置 coherent=1。这一错误处理经汇总阶段复核成立。

要求：只有已证明共享 backing 的具体本地边界可以省复制；跨节点目录、
版本、subscriber 和 handoff 提交不能因本地 SHM 而消失。join/attach 失败
必须返回可处理的结果，不能继续宣称映射已 coherent。
验收：两个 distinct runtime/SHM，真实 guest 写入经生产 commit 到远端
权威目录，检查数据和版本；禁止测试侧代提交。

G3. force_local 用启动时长掩盖调度依赖，绕过 admitted CPU 放置
    [Codex R2；CC N3；DSH D3]

wavevm-cpu.c:392/661/2495：60 秒 sticky 可让原定 remote 的 vCPU 改在
frontend 执行；注释明确以 Cirros boot-to-login 为依据。还有每 VM 的
STW 互斥与本地 vCPU/设备推进互相依赖的问题。
DSH A/B 补充：默认可登录，禁用 force_local 的那次 240 秒无 login，串口
出现 CPU#1 delay_tsc soft lockup。该反例增强了“当前方案依赖缓解”的证据，
不能推算成 guest 永远不可能启动，也不能证明整个启动过程全是本地执行。

要求：闭合远端执行等待与本地进展之间的调度关系，保留 manifest 的执行
放置/资源记账。允许有依据的时间片、公平调度和有界同步，不允许把覆盖
某镜像启动时长的强制本地执行当成修复。把 60 秒做成配置不是解决方案。
验收：默认生产路径完成 guest；登录后受控负载期间，指定远端完成计数
持续增加，同时验证本地/远端工作归属，不只看启动早期累计一次执行。

G4. page-install / push fence 仍以 sleep 代替 ACK，且错误被回复为成功
    [Codex R3；DSH D5]

slave_hybrid.c:4598 的 helper barrier 发 UDP 后睡 2ms，不等各 helper
cookie ACK；main_wrapper.c:1475 忽略/仅打印 barrier 错误后仍回全零成功。
另一个 notify_tcg_page_installed(:1706) 等不到 ACK 后睡 150ms，也返回
成功；即便收到了数据，其分支也未严格核对 ACK 帧和 cookie。

要求：复用现有 PUSH_BARRIER_ACK，关联实际所需的 ACK 与页面 APPLY，
错误传回 fence/handoff。没有 ACK 不能靠延长 sleep 宣称完成。
验收：暂缓某个需要的 APPLY/ACK 时不得提前成功；恢复则完成，超时则有界
失败，不启动依赖该页的 slice。只需针对性验证，不要求完整网络故障框架。

G5. vCPU 完成记录在 horizon 前被清掉，现有重放测试已失败
    [Codex R4；DSH D2/2.3]

vcpu_coordinator.c:883–897 在 complete() 返回后立即 entry_clear。
回调仅排队 ACK，并不代表上层已收到/重试窗口结束；其失败也会清记录。
Codex 和 DSH 均复现 test_vcpu_coordinator.sh rc=1：
  vCPU coordinator test: accept an exact duplicate exit idempotently

要求：区分局部 waiter 与语义完成记录，满足约定的查询/重放 horizon。
容量不足应在执行前背压，不能靠提前遗忘结果撑过 guest 启动。
验收：原测试通过；同一操作的重复结果、查询、重发不能换成新 sequence
或第二次执行；冲突 payload 继续拒绝。

G6. ESTALE 后只换 base_version，却重发旧整页，会覆盖别人已提交的数据
    [Codex R5；另外两份报告未单独核对，不应因缺少“票数”而删除]

wavevm-user-mem.c:1818/2225 读回 mat_page 后未合并其内容，只取新版本，
再发送旧 HVA/current_snapshot 的 4KiB。尤其 slave 注释明确写保留旧快照。
例：同版 [x=0,y=0]，B 提交 y=1，A 的旧整页 [1,0] 遇 ESTALE 后只更换
版本号再提交，就能抹掉 B 的 y=1。这与 memory-consistency §4.3 直接冲突。

要求：真正 RESYNC 并处理真实写集，或明确失败；不能给旧整页换新版本标签。
验收：同页不同字节并发修改、一次 stale/resync 后，两者已确认修改均保留。

G7. 内核 committer 将缺路由/AUTO_ROUTE 也短路为提交成功
    [Codex R6-1；CC N4]

kernel_backend.c:1868 把 !WVM_IS_VALID_TARGET 与确认本地 owner 合并。
logic_core.c:1383 的无 context、未绑定 snapshot、projection 不覆盖 GPA
恰好返回 AUTO_ROUTE。这不证明本地权威已接收写入，却走正常 reprotect/free。
真实本地目录也需完成 canonical 版本/订阅者语义，不能只省掉网络 send。

要求：未知路由 fail closed 并保留待结算脏数据；本地 owner 的提交走相同
权威语义。不是“为单机无对端测试把 -ENODEV 改成成功”。
验收：无所需 snapshot 时显式失败；确认本地时能观察权威版本及数据更新。

G8. STOP drain 没统计正在发送的 ACK，且 reply worker 可无限阻塞
    [Codex R7；DSH D6]

vcpu_service.c:169 在 write_reply 前清 entry；drain 只看 pending/queued。
发送 socket 满时 poll(POLLOUT,-1)，destroy 又无界 join。
Codex 已复现：发送缓冲填满、receiver 不读时，drain(timeout=20ms) 仍返回 0。
DSH 的 idle/stub STOP PASS 并不覆盖这一触发条件。

要求：跟踪 ACK 正在发送的状态，drain 与发送/退出都要有界且结算错误。
验收：慢/断开的 receiver 不造成假 drain 或无界 STOP；正常 STOP 和
双 VM 杀一保一仍保持。无需再设计一套通用 shutdown 平台。

G9. 最终 guest 判据可由启动横幅满足，且总 PASS 早于 STOP 判定
    [Codex R8；CC N2；DSH D4]

test_guest_smoke.sh:359/367 把 READY、WaveVM、region_add 等当作两个
remote 标志。注册 RAM、启动 helper 不能证明远端完成过 guest 工作。
其 guest CPU smoke 的失败被 || true 吞掉；OVERALL=PASS 写在 STOP 之前。
当前 guest 脚本只起一个 compute 实例，这层可验证启动，不能单独证明
“多个 compute 的 CPU/内存参与”，也不能用 G2/G3 已绕开的链路来拼证据。

要求：记录 VM/incarnation、源/目标实例、执行完成数、权威页数据/版本或
关联 fence；在受控 guest 负载前后取增量。总结果在必要 STOP/cleanup 后
统一生成，失败时不能残留 OVERALL=PASS。
允许同机多实例和分层验收组合；组合必须是同一生产路径，不能以只覆盖
初始化或另一条 helper 路径的 PASS 替代当前 guest 的远端工作证据。

G10. memory_service 的严格构建失败，当前 A14 验证入口也被堵住
     [Codex R9；DSH D2/2.2]

memory_service.c:1477/1494 两个未使用 static 函数触发既有 -Werror。
Codex、DSH 均复现；fresh remote_mem 包为 PARTIAL：
  rc_dir=0 rc_mem=1 rc_fence=0 rc_g4=1 rc_g4_kvm=1
要求：清理不用代码或恢复必要调用，保留严格编译；不能删 Werror 凑绿。
修完先跑现有 memory_service 与 TCG/KVM A14，再谈这部分数据面通过。

五、对另外两份报告的取舍和纠正

1. 不采纳 CC N5 的“发送睡眠时 per-CPU context 随迁核串位”结论。
   当前 kernel_backend.c:768–823 是 hash_ptr(current) 的 task-bound 表，
   并非它假设的 per-CPU 槽。仅凭迁核理由不能成立；本次不为它派修复任务。
   这不等于对该表所有可能竞态作了全面安全证明。

2. 不采纳“先修改纲领允许 8-bit Mode A”作为本轮闭合方案。
   kernel-accelerator §1.2 已明确 full-u32；没有在跑业务，也没有保留旧
   路径的要求。两份报告提出的收缩范围属于新设计决策，用户并未授权。
   暂时安全拒绝与实现完成要分别记录，不能通过改规格消掉当前缺口。

3. 不采纳“TCG 并行合同没写清，所以可直接改成永久 STW”的说法。
   vcpu-handoff §8 已写 per-vCPU ownership、独立 handoff 可并发、有界
   同步不得永久串行全部 vCPU；baseline §15 也要求保留正常并发/批处理。
   是否改变目标需另行讨论。本轮先遵守现有合同，不自动下调承诺。
   另一方面，正常 time slice 或有界 backpressure 不是看到毫秒数就违规。

4. 不把“WVM_TCG_DISABLE_FORCE_LOCAL=1 这个调试开关必须永远保留且能过”
   发明成新的独立合同。需要的是生产默认路径不依赖启动专用绕过，并能
   正确持续远端执行；A/B 是定位证据，可以随根因修复调整或删除。

5. CC 明说未重新核对的 A01/A03/A05/A06/A10–A13 不能直接重列为已确认
   活跃缺陷，也不能说它们已全部通过。本轮先解决有具体当前证据的事项；
   若其他 agent 指出可达的现存触发，再追加，不重开无边界历史清单。

六、给 Grok 的推进顺序与收尾要求

建议按依赖推进，每条“生产修复 → 编译和少量针对性验证 → 下一条”：

1. 先清 G10 恢复测试入口，同时修 G5 结果保留的明确回归。
2. 处理 Mode A 的 G1/G7，不再靠低 ID 测试和缺路由成功短路拿 PASS。
3. 收 TCG 内存 G2/G4/G6，再收调度 G3；相关根因耦合时可在同一小步处理，
   但提交说明必须能区分“真实同步”与“绕过远端”。
4. 修 G8；把 G9 的真实证据采集与前面修复一起接好。
5. 最后重跑受影响的 s6 / remote_mem / guest 场景，按同一源码与二进制
   记录 backend、topology、capability、manifest、远端数据/执行和清理结果。

无需每改一处都重跑全部矩阵或等完整 guest 启动；也无需先做 HA/迁移、
全插件故障引擎和完整 fault injection。最终则不能用旧二进制/旧 PASS
代替新工作树的验收。

证据只保留必要小包：源码/工作树标识、二进制 hash、命令及非敏感环境、
结果、计数/页版本、有限日志和 cleanup。放到可跨重启的位置，不必提交
镜像、巨型原始日志、密钥或全部 /tmp。引用 /tmp 的 plan 不等于长期归档。

完成回应请按 G1–G10 给出“生产改动位置 + 一个必要的验收结果”；没完成
就明确 PARTIAL。单纯把变量名/魔法数挪位置、扩大 regex、缩小测试身份、
延长 timeout 或让矩阵忽略子项，均不视为闭合。
